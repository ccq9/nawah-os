# ADR-0001 — قرار أول بناء (bootstrap)

الحالة: مقبول (M0). التاريخ: 2026-10-17. الدليل: E0 — evidence/20261017T210133Z-c049336e-001 (بناء) و evidence/20261017T210133Z-c049336e-002 (إقلاع).

## القرار

1. الهدف الأول: x86-64، إقلاع UEFI، مختبر QEMU q35 مع OVMF (edk2 2024.02)، معالج افتراضي واحد، 512 MiB.
2. اللغة: C (معيار C11 حر freestanding) مع Assembly مضمّن محدود، عبر clang 18.1.3 بهدف x86_64-unknown-windows وlld-link 18.1.3 لإنتاج PE32+ لتطبيق EFI. السبب: الفرضية الأولى (Rust، هدف x86_64-unknown-uefi) محجوبة شبكيًا في هذه البيئة (docs/ENVIRONMENT.md)؛ clang+lld متاحان وأثبتت E0 السلسلة. الانتقال إلى Rust لاحقًا قرار مستقل يحتاج ADR جديدًا وتجربة مكافئة.
3. شكل النواة: نواة معيارية (monolithic-modular) تجمع الجدولة والذاكرة والعمليات والأمن الأساسي والإدخال/الإخراج؛ الواجهة وخدمات المنتج في وضع المستخدم. لا تُسمّى microkernel.
4. صيغة الصورة لأول بناء: صورة PE/COFF واحدة تعمل تطبيق UEFI (kernel stub) تجمع خريطة الذاكرة وبيانات framebuffer وجداول العتاد ثم تنفذ ExitBootServices وتتابع نواةً. فصل محمل الإقلاع عن النواة قرار لاحق (ADR مستقل) عندما تحتاج النواة تحميلًا بصيغة مختلفة.
5. قناة التشخيص: COM1 (0x3F8) بأسطر ASCII بعقد docs/contracts/boot.md؛ رمز الخروج عبر isa-debug-exit في المختبر فقط.
6. المشغّل: python3 3.13 عبر tools/project.py.

## البدائل داخل الهدف

- Rust + uefi target: مفضل أمنيًا؛ محجوب الآن. يُعاد تقييمه عند توفر الشبكة أو rust-std محليًا.
- محمل إقلاع خارجي (مثل Limine) + نواة ELF: يختصر لاحقًا لكنه يضيف تبعية ترخيص ومسار ABI إضافيًا قبل الحاجة؛ مؤجل.
- gnu-efi / mingw-w64: غير مثبتة؛ لا ميزة على clang+lld.

## التنازلات والمخاطر

- C بلا أمان ذاكري: يُعوَّض بتحصين (-Werror، -fno-builtin، حدود صريحة) ومراجعة parsers وfuzzing على المضيف لاحقًا (البند 15).
- OVMF 2024.02 مع QEMU 8.2.2 بلا KVM: أبطأ، لا أثر على صحة الأحكام.

## أثر التغيير

تغيير اللغة أو شكل الصورة يُبطل أدلة M1 ويعيد فتح REQ-M1-*.
