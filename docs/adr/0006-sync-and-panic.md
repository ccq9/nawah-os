# ADR-0006 — التزامن الأولي وسياسة panic (WP-11)

الحالة: مقبول — منفَّذ ومُغلق 2026-10-18 بدليل CI run 39098204104 (TST-M2-LOCK-IRQSAVE / LOCK-REENTRY / PANIC-CODE PASS؛ كل أجنحة M1/M2 خضراء).

## القرارات

1. **قفل واحد في M2**: `IrqSpinLock<T>` (kernel/src/sync.rs): `lock()` يحفظ RFLAGS.IF ثم `cli` ثم استحواذ ذرّي (`compare_exchange` على حقل الحائز = cpu_id+1)، والحارس عند الإسقاط يحرر أولًا ثم يعيد IF إن كان مرفوعًا. السبب: المقاطعات تعمل منذ WP-10، وأي قفل يُؤخذ من سياق مقاطعة لاحقًا (M3+) دون تعطيل IF يُنتج تعليقًا ذاتيًا.
2. **كشف إعادة الدخول**: حائز القفل هو المعالج نفسه → panic `K_E_LOCK_REENTRY|lock=<name>|cpu=<n>` بدل الدوران إلى الأبد. على معالج واحد هذا هو التشخيص الصحيح الوحيد؛ مع SMP (M3) يبقى صحيحًا لأن المقارنة بالحائز لا بالعدّ.
3. **وحدة التحكم مقفلة**: `kprintln!` = استحواذ لكل سطر؛ لا تداخل أسطر بين السياقات. مسارات لا تعود (panic، استثناء قاتل) تكسر القفل أولًا (`force_unlock`، unsafe موثق) وتسجل `console_was_locked`.
4. **المخصص مقفل**: حالة PMM داخل `IrqSpinLock<Pmm>`؛ كل دالة عامة = عملية واحدة تحت القفل؛ لا طباعة تحت قفل المخصص (ترتيب أقفال بسيط وموثق).
5. **panic.rs وحدة مستقلة** تحمل `#[panic_handler]` وسياسة الإنهاء (0x11 في المختبر، halt خارجها)، وحارس panic متداخل، و`fatal(code)` لفشل الإقلاع الحرج بدل `print + halt` الصامت الذي كان يُنتج مهلة بدل نتيجة.
6. **تعديل سياسة unsafe**: الوحدتان `kernel/src/sync.rs` و`kernel/src/panic.rs` تُضافان إلى قائمة الوحدات المسموح فيها (tools/check-unsafe.sh)؛ الأولى هي الموضع القانوني لـ UnsafeCell/Deref في بدائي التزامن، والثانية لكسر قفل وحدة التحكم. خط الأساس 103 سطرًا (كان 97): sync 4، panic 1، trap +1 (كسر القفل في المسار القاتل)، pmm 0 صافي (استبدال وصول BootCell بـ `unsafe impl Send`).
7. **الوثيقة المعيارية**: docs/policies/panic.md (ما هو panic، فشل الإقلاع الحرج، نفاد الموارد بلا panic، الاستثناءات، الأقفال، الاختبارات).

## الاختبارات

- TST-M2-LOCK-IRQSAVE: IF=0 داخل القفل و=1 بعده؛ من حالة IF=0 يبقى 0؛ المؤقت الدوري الحقيقي لا يُسلِّم نبضة أثناء الحمل (20 ms) ويستأنف بعده (≥10 في 20 ms)؛ try_lock يفشل أثناء الحمل وينجح بعده؛ القيمة المحمية 2.
- TST-M2-LOCK-REENTRY (سلبي): إعادة استحواذ → panic بالرمز، خروج 35.
- TST-M2-PANIC-CODE (سلبي): `panic!` صريح → سطر panic بـ build id والموقع `kernel/src/ktest.rs:` والرسالة، خروج 35.
