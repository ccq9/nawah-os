# ADR-0013 — التخزين: PCI/ECAM، virtio-blk، طبقة الكتل (WP-18 الجزء 1)

الحالة: مقبول — منفَّذ ومُغلق 2026-10-18 بدليل CI run 39111422991 (TST-M3-BLK-READ / BLK-USER-CR3 / BLK-PERSIST / FAT32-READ / FAT32-WRITE / FAT32-PERSIST / FAT32-TOOL PASS؛ أثر TST-M1-BOOT بسطور `kernel|pci|…`، `kernel|blk|…|mmio_shared=1|…|selfcheck=1`، `kernel|fat32|…|selfcheck=1`). الجزء 1 (الجهاز) أثبته CI run 39108867621؛ دروس التشغيلات: 39108491755 (ECAM 0xE0000000)، 39108867621 (مخزن الاختبار إطار)، 39109529224 (عدّادات FSInfo)، 39110182649 (نافذة MMIO المشتركة §8).

المراجع: Virtio 1.3 (S42): §4.1 النقل عبر PCI (المعرّفات، `virtio_pci_cap`، `virtio_pci_common_cfg`، عنوان الإشعار)، §3.1.1 ترتيب التهيئة، §2.7 الطابور المنقسم، §5.2 جهاز الكتل؛ ECAM ورأس تهيئة PCI (S43)؛ ACPI 6.5 جدول 5-6 للتوقيع MCFG (S33)؛ ADR-0004 (الخريطة المباشرة و`map_mmio`)، ADR-0007 §4 (فتحات PML4 المشتركة)، ADR-0005 (I/O APIC مقنَّع).

## القرارات

1. **الاكتشاف عبر MCFG/ECAM لا عبر منافذ 0xCF8/0xCFC**: جدول MCFG يعطي نافذة ECAM (المختبر: OVMF على q35 يضعها عند 0xE0000000، المقطع 0 — قاسها CI run 39108491755 بعدما افترض الأوراكل 0xB0000000)؛ صفحة تهيئة كل دالة تُرسم UC عند أول استعمال بـ `map_mmio`. يُعدَّد الناقل الجذري فقط (q35 يحمل الأجهزة عليه)؛ تتبع الجسور مؤجَّل (M4). قراءة BAR تقيس الحجم بكتابة الآحاد ثم تُعيد القيمة.
2. **virtio-pci الحديث فقط** (VERSION_1 إلزامي؛ المختبر يمرر `disable-legacy=on`): القدرات الخاصة بالبائع (0x09) تحدد مواضع common/notify/device داخل BARs؛ الميزات المقبولة VERSION_1 وFLUSH لا غير؛ يُتحقق من بقاء FEATURES_OK بعد كتابته؛ MSI-X غير مستعمل وINTx معطَّل (بت 10 في Command) — **الإكمال بالاستطلاع** على `used.idx` بحد دورات (مهلة = `K_E_BLK_TIMEOUT`) لأن المقاطعات ليست مطلوبة للتزامن وتبقى I/O APIC مقنَّعة (ADR-0005)؛ يُعاد النظر مع MSI-X عند الحاجة إلى تزامن أعلى.
3. **طابور منقسم واحد بحجم 16 في إطار واحد** (desc عند 0، avail عند 0x400، used عند 0x800؛ المحاذاة 16/2/4 محفوظة)، وإطار للرأس وبايت الحالة، و16 إطارًا متجاورًا مخزنًا وسيطًا (bounce) لطلب ≤ 64 KiB. كل طلب = سلسلة ثلاثة واصفات (رأس للقراءة، بيانات، حالة للكتابة) بترتيب الذاكرة الذي تفرضه المواصفة (واصفات → خانة الحلقة → حاجز → idx → حاجز → إشعار). طلب واحد في كل مرة خلف `IrqSpinLock`.
4. **لا `unsafe` في السواقات**: الوصول إلى MMIO عبر `arch::mmio` (6 دوال متطايرة بعقد «عنوان من map_mmio») وإلى إطارات DMA عبر `mm::dma` (قراءة/كتابة متطايرة وعرض بايتات لإطارات يملكها السائق) — فتبقى `drivers/` خارج قائمة الوحدات المسموح فيها بـ unsafe ويُدقَّق المبدآن وحدهما. خط أساس unsafe 160 (كان 148): mmio +6، dma +6.
5. **طبقة الكتل** واجهة متزامنة: `read/write` بمضاعفات 512 بايت حتى 64 KiB ضمن السعة (وإلا `K_E_BLK_RANGE`)، و`flush` يرسل VIRTIO_BLK_T_FLUSH (أو يعود فورًا إن لم يعرض الجهاز FLUSH لأن كتاباته مستقرة حينها بحسب §5.2.6.2).
6. **قرص المختبر**: صورة raw 64 MiB بنظام FAT32 يبنيها `tools/project.py` عبر `tools/fat32.py` لكل تشغيل (ملفات المختبر + نمط `(sector*7+i)&0xFF` في آخر 8 قطاعات، خارج أي عنقود مخصَّص) وتُرفق لكل تشغيل على pc-qemu بـ `virtio-blk-pci`؛ فحص ذاتي في كل إقلاع يقرأ القطاع 0 ويرسل flush. **حالات متعددة المراحل** في الأوراكل: مراحل متتابعة على الصورة نفسها (تُعاد بناؤها عند المرحلة الأولى فقط)، لكل مرحلة علاماتها، وعلامات الحالة تُفحص على تسلسل كل المراحل — هكذا يثبت اختبار الثبات بقاء البيانات عبر إعادة تشغيل QEMU (بناء مطابق: وسم يحمل build id).

7. **FAT32 (الجزء 2)**: تنفيذ في النواة (`fs/fat32.rs`، بلا unsafe): قراءة BPB والتحقق من كل حقل (512 بايت/قطاع، FAT32 بالشكل والعدد ≥ 65525 عنقودًا، الجداول داخل السعة)، قراءة قطاعًا قطاعًا بلا ذاكرة مخبّأة، أسماء 8.3 فقط (LFN تُتجاوز)، إنشاء/كتابة (إلحاق أو استبدال)/حذف/سرد، تحديث نسختي FAT معًا، وحدّ 64 MiB للملف. **أداة مستقلة** `tools/fat32.py` (Python، تنفيذ ثانٍ مكتوب على المواصفة لا على شيفرة النواة) تهيئ صورة المختبر (64 MiB، 128992 عنقودًا، الملفات /HELLO.TXT و/PATTERN.BIN و/DIR/INNER.TXT، ونمط خام في آخر 8 قطاعات) وتقرأ ما كتبته النواة بعد التشغيل (`host_checks` في الأوراكل: `fat32.py expect/check` و`fsck.fat -n` من dosfstools كمنفّذ ثالث). الاختبار المضيف TST-M3-FAT32-TOOL يثبت الأداة نفسها.

8. **نافذة MMIO مشتركة في النصف العلوي (تعديل بعد CI run 39110182649)**: `vmm::map_mmio` كان يرسم سجلات الجهاز هويةً عند عنوانها الفيزيائي؛ صَلُح ذلك لـ LAPIC وECAM (الفتحة 0 المنسوخة إلى كل فضاء) وأخفق مع BAR الـ virtio الذي يضعه OVMF عند `0xC0_0000_0000` — أي في فتحة PML4 رقم 1، نطاق المستخدم الذي لا يُنسخ — فنجحت فحوص الإقلاع واختبارات النواة (CR3 النواة) وأخفق أول `open` من عملية بـ #PF نواة عند `0xC000000014` (قراءة `device_status`). القرار: نافذة `MMIO_BASE = 0xffff_a800_0000_0000` (فتحة PML4 رقم 336، تُضاف إلى الفتحات المُهيأة مسبقًا في ADR-0007 §4) يوزعها `map_mmio` تصاعديًا UC/RW/NX عبر جداول فضاء النواة، مع سجل نطاقات (64) يعيد العنوان نفسه لنطاق مرسوم من قبل ويرفض التداخل الجزئي؛ لا إلغاء رسم (الأجهزة لا تُنزع). كل مستدعٍ يستعمل العنوان المعاد لا الفيزيائي (LAPIC كان يتجاهله). يثبته TST-M3-BLK-USER-CR3 (قراءة قطاع وflush تحت CR3 فضاء مستخدم جديد تساوي قراءة النواة) وحقل `mmio_shared=1` في سطر `kernel|blk|` كل إقلاع؛ واختبارات تطبيقات الملفات (WP-19) هي التي كشفته.

## الاختبارات

- TST-M3-BLK-READ: الجهاز حاضر بسعة 131072 قطاعًا؛ قراءة آخر 8 قطاعات تعيد النمط بلا اختلاف (أول البايتات c8c9cacb)؛ القراءة عند السعة وبطول 100 بايت مرفوضتان؛ الإطارات متساوية (درس CI run 39108867621: مخزن الاختبار نفسه إطار من الكومة فيُؤخذ قبل القياس).
- TST-M3-BLK-USER-CR3: سجلات الجهاز داخل `0xffffa8…` (النافذة المشتركة)، وقراءة القطاع 0 وflush تحت CR3 فضاء مستخدم فعّال تنجحان وتساويان قراءة النواة (توقيع 55AA)، الفضاء يُهدم والإطارات متساوية — انحدار CI run 39110182649.
- TST-M3-BLK-PERSIST: المرحلة 1 تكتب وسم `NAWAH-PERSIST|<build id>` ونمطًا في القطاعات الخام 131056..=131063 (خارج أي عنقود يخصصه نظام الملفات) ثم flush وتقرأ؛ المرحلة 2 (إقلاع جديد على الصورة نفسها) تجد الوسم والمعرّف والنمط سليمة — نجح في CI run 39108867621.
- TST-M3-FAT32-READ: ملفات الأداة تُقرأ بايتًا بايتًا (بما فيها قراءة من إزاحة 20000 في ملف متعدد العناقيد)، السرد 3 إدخالات، والرفض برموز `K_E_FS_NOT_FOUND/NOT_A_DIRECTORY/BAD_NAME/IS_A_DIRECTORY`.
- TST-M3-FAT32-WRITE: إنشاء وكتابة 3006 بايت (6 عناقيد) وقراءة واستبدال في المنتصف وحذف؛ العناقيد الحرة تعود 128948؛ ثم `fsck.fat -n` و`fat32.py check` على الصورة.
- TST-M3-FAT32-PERSIST: مرحلتان: إنشاء `/PERSIST.TXT` بمعرّف البناء ثم sync، وإقلاع جديد يقرأه؛ ثم الأداة المضيفة تقرأ البايتات نفسها من الصورة.
- TST-M3-FAT32-TOOL (مضيف): الأداة ذاتها.
- أثر TST-M1-BOOT: `kernel|pci|ecam=0xe0000000|segment=0|functions=7|list=…1af4:1042…`، `kernel|blk|device=0x1042|…|capacity_sectors=131072|queue_size=16|…|mmio=0xffffa8…|mmio_shared=1|…|read_ok=1|flush_ok=1|code=ok|selfcheck=1`، و`kernel|fat32|label=NAWAHLAB|…|clusters=128992|…|free_clusters=…|hello_size=24|hello_ok=1|code=ok|selfcheck=1` (كان `free_clusters=128948` حتى WP-22؛ منذ WP-23 تحمل الصورة التطبيقات المبنية تحت `/SYSTEM` فيتغير العدد مع حجمها، والمطابقة الدقيقة لعدّاد الحرية تبقى على المضيف بـ `fsck.fat -n` و`fat32.py check` بعد كل كتابة).

## ما لم يُحسم

- MSI-X والإكمال بالمقاطعة؛ طلبات متوازية؛ أجهزة خلف جسور؛ FAT32 (الجزء 2 من WP-18) ثم VFS (WP-19).
