# عقد الجلسة والقفل — الإصدار 0 (مسودة M5، ADR-0019 §5)

مسودة تخطيط: تُجمَّد كإصدار 1 عند إغلاق WP-37 بدليل CI؛ ما لم يُنفَّذ منها لا يُعدّ مدعومًا.

- **الخدمة** `session`: تملك حالة القفل (`locked`/`unlocked`/`no_session`) ورمز الجلسة (من `auth` LOGIN)؛ شاشة الدخول/القفل سطح تملكه هي؛ إدخالها يصل مباشرة من `input` (input.md v2: التوجيه إلى الجلسة برمزها)، لا عبر الـ compositor ولا عبر تطبيق.
- **الانتباه الآمن**: Ctrl+Alt+Del تحجزه `input` وتسلّمه للجلسة دائمًا → قفل فوري (أو شاشة دخول إن لا جلسة).
- **التعافي**: الـ compositor عند بدئه/إعادة تشغيله يسأل `STATE` ويعرض سطح الجلسة إن كانت مقفولة؛ `input` عند بدئها/إعادة تشغيلها تسأل `ROUTE` فتوجّه إلى الجلسة إن كانت مقفولة؛ انهيار `session` → الـ compositor يحجب كل النوافذ ويعرض «إنقاذ مصادَق» حتى تعود `session` (يعيدها المدير) وتصادق من جديد؛ لا يُفتح سطح المكتب تلقائيًا أبدًا.
- **الطلبات** (قناة عميل عبر `CONNECT session`، لـ display وinput فقط حسب البيان): `STATE` → `OK locked|unlocked|no_session`؛ `LOCK` + رمز الجلسة → `OK`؛ من `input`: `SAK` → `OK` (تقفل)؛ من الجلسة إلى auth: LOGIN/LOGOUT/LOCK/UNLOCK (auth.md).
- **حدود الاستبقاء المعلنة**: القفل يحفظ النوافذ وأسطحها؛ انهيار الـ compositor يفقد المخازن الخلفية لا أسطح العملاء (VMO يملكها العميل) فتُعاد بـ `ATTACH` بعد إعادة التشغيل؛ البيانات غير المحفوظة في تطبيق مات ليست موعودة.
- **الاختبارات الحاكمة**: TST-M5-LOCK-SURVIVES، TST-M5-AUTH-INPUT-ISOLATED، TST-M5-LOGIN-SCREEN.
