# سياسة panic ونفاد الموارد والأقفال (M2، WP-11)

المرجع المعياري: ADR-0006. الكود: `kernel/src/panic.rs`، `kernel/src/sync.rs`، `kernel/src/console.rs`.

## 1. ما هو panic

panic = انتهاك ثابت (invariant) داخل النواة: حالة لا يستطيع الكود المتابعة منها بأمان. ليس وسيلة للإبلاغ عن فشل متوقع.

- المخرج: سطر واحد ASCII على القناة التشخيصية:
  `OSX|<build_id>|kernel|panic|loc=<file>:<line>:<col>|console_was_locked=<0|1>|msg=<message>`
  الرسالة تبدأ برمز مصنَّف `K_E_*` عند توفره (مثل `K_E_LOCK_REENTRY|lock=pmm|cpu=0`).
- الإنهاء: في المختبر `isa-debug-exit` بالرمز 0x11 (حالة خروج QEMU = 35)؛ بدون جهاز المختبر: `cli; hlt` إلى الأبد. سياسة الإنتاج (إعادة تشغيل بعد مهلة، حفظ تفريغ) قرار مؤجل إلى M9 بسجل قرار خاص.
- panic أثناء panic: سطر ثابت `OSX|?|kernel|panic|nested|stopping` دون آلية التنسيق ثم الإنهاء نفسه.
- قبل الطباعة يُكسر قفل وحدة التحكم (`CONSOLE.force_unlock`) لأن مسار panic لا يعود أبدًا إلى الكود الذي قد يحمله؛ القيمة `console_was_locked` تُسجَّل للتشخيص.

## 2. فشل الإقلاع الحرج

فشل لا يمكن المتابعة بعده (BootInfo غير صالح، فشل بناء جداول الصفحات، غياب MADT، تعذر معايرة المؤقت) يمر عبر `panic::fatal(code)`: شكل السطر ورمز الخروج نفسهما، والرسالة هي الرمز المصنَّف (`K_E_VMM_*`, `K_E_ACPI_*`, `K_E_APIC_*`, `K_E_TIMER_NOT_CALIBRATED`, ...). لا حلقة انتظار صامتة.

## 3. نفاد الموارد: لا panic

- مخصص الإطارات: النفاد يعيد `None`؛ التحرير الخاطئ يعيد `Err(PmmError::...)`.
- جداول الصفحات: `Err(MapError::OutOfFrames | Conflict | Unaligned)` تُرفع إلى المستدعي.
- خرائط ACPI: المصفوفات الثابتة ممتلئة → العنصر يُحسب في `dropped` ولا يُفقد الإقلاع.
- القناة التشخيصية غائبة → البايتات تُسقط بعد حدّ دوران محدود؛ لا تعليق.

## 4. الاستثناءات

- كل الاستثناءات قاتلة إلا `#BP` (يستأنف). القاتل يطبع ثلاثة أسطر تشخيص (الإطار والمسجلات) بعد كسر قفل وحدة التحكم، ثم يُنهي بالرمز 0x48 + المتجه.
- حد التداخل 3: عنده رسالة ثابتة بلا تنسيق ثم توقف؛ بعده لا مخرجات.
- المقاطعات (المتجهات ≥ 32) ليست استثناءات: تُعدّ ولا تطبع ولا تخصص ولا تأخذ أقفالًا (M2)؛ متجه بلا معالج يُعدّ «غير متوقع» ولا يُسقط النواة.

## 5. الأقفال

- النوع الوحيد في M2: `IrqSpinLock<T>` (irqsave): يعطل IF على هذا المعالج، يستحوذ، والحارس يعيد IF إلى حالته السابقة عند الإسقاط؛ التحرير قبل إعادة IF.
- إعادة الاستحواذ على قفل يحمله المعالج نفسه = خطأ برمجة يُكشف ويتحول إلى panic `K_E_LOCK_REENTRY|lock=<name>|cpu=<n>` بدل تعليق صامت.
- `try_lock` لا يدور؛ `force_unlock` (unsafe) لمسارات لا تعود فقط (panic، استثناء قاتل).
- الأقفال الحالية: `console` (سطر واحد لكل استحواذ)، `pmm` (عملية واحدة لكل استحواذ). ترتيب الأقفال: لا يُؤخذ `console` وأنت تحمل `pmm` (المخصص لا يطبع).
- المعالج الواحد في M2: هوية المعالج ثابتة 0 (`arch::cpu_id`)؛ M3 يجعلها حقيقية دون تغيير الواجهة.

## 6. الاختبارات

TST-M2-LOCK-IRQSAVE (IF يُمسح داخل القفل ويُستعاد؛ المؤقت محجوز أثناء الحمل ويستأنف بعده؛ try_lock)، TST-M2-LOCK-REENTRY (إعادة استحواذ → panic بالرمز)، TST-M2-PANIC-CODE (panic يطبع build id والموقع والرسالة ويخرج بـ 35)، وفحص `console_was_locked` في سطر panic.
